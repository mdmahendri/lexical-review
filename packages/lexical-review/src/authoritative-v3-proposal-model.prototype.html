Which state is the truth?

This throwaway model tests whether version 3 can keep accepted content, immutable revision proposals, mutable proposal drafts, and the live Lexical editor understandable without making Lexical JSON authoritative. Press the buttons freely or follow a guided walkthrough.

Hypothesis: a React-free review document is the only authority for accepted state and independently identifiable proposals. A mutable proposal draft stays in the live Lexical workspace and never enters that ledger. Export computes its portable target once and mints immutable identity. Lexical node keys and selection remain local.
1. Authoritative review document

Accepted paragraphs, fingerprint, and immutable pending proposals. Complete proposal creation and atomic accept/reject work without a live editor. A UI may call the same core operations.

2. Live Lexical projection and drafts

Rebuildable review segments plus mutable draft text, local anchors, node keys, and selection. Draft keystrokes cause no proposal-ledger remapping; core IDs travel as node metadata. While a draft is open, core resolution waits for export or discard so its coordinate frame cannot shift underneath it.

incremental intent → Lexical-local draft → export boundary; complete intent → core proposal directly; explicit resolution → core resolver

Paragraph split and merge are structural proposals, not insertion proposals: split creates a right paragraph identity and moves existing suffix text; merge retires the right identity and rehomes its existing text. Neither operation inserts a text fragment.

Lexical itself does not require React. A draft belongs to an incremental Lexical editing session—usually a visible React editor here, but it may be headless. “Programmatic” means the caller already has a complete semantic proposal or resolution request; that caller may still be UI code.

This model intentionally does not settle compound gestures, clipboard transfer, or post-resolution selection; those remain separate Wayfinder decisions. Fingerprints are symbolic in this prototype, not JCS hashes.
