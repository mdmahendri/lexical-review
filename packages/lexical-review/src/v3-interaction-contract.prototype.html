Throwaway prototype

One interaction contract, many noisy input routes

Drive candidate version 3 rules through proposal boundaries, local authoring, finalized work, formatting, paragraphs, clipboard, IME, and preview projections. The prototype is a discussion tool, not production code or a public API draft.

Question being tested: Can one route-neutral semantic state machine make every in-scope review interaction deterministic while preserving accepted state, pending work, projection, and logical selection on every refusal?
Candidate answer: Browser events, Lexical commands, toolbar actions, clipboard actions, IME sessions, and programmatic calls first normalize into one semantic intent applied to session-local Lexical review state. Review-aware nodes carry accepted content, finalized proposals, and the active draft; the visible review projection is reconciled from that state. Raw browser event order never changes the normative outcome.
Two serialization paths: The native Lexical-shaped review document loads and saves review state directly. A Web Editor Revisions v1 interchange document enters or leaves only through a validated adapter with a mapping report. WER constrains portable data and adapter outcomes, not live nodes, algorithms, or native serialization.
Evidence boundary: The repository resolves Lexical 0.49.0. Its tagged source contains different Android Chrome, Firefox, Safari/WebKit, and iOS composition/deletion paths. Those facts justify adapter-specific normalization and browser conformance tests; they do not define Lexical Review semantics. Vendor observations are likewise informative, never normative.

      Resolved invariants

      • Settled A caret adjacent to finalized work must carry an accepted-side association. The service supports an action only when that association makes the accepted target unique; an ambiguous visual boundary refuses.
      • Settled Continuous text authoring—insert, delete, replace, paste, and IME—uses a mutable local draft. Complete discrete intentions—format, split, and merge—create finalized proposals immediately in Lexical review state. Proposal finalization is not document serialization.
      • Settled Active composition is a semantic critical section. Proposal finalization and resolution refuse until composition ends or is cancelled; interim DOM variation is adapter-local.
      • Settled A formatting adapter resolves “toggle” into an explicit desired value before calling the semantic service. A collapsed toggle only changes future local input formatting and creates no proposal by itself.
      • Settled Review-changing edits run only in the review projection. Projection previews are read-only, but explicit accept/reject remains available because it acts on revision proposals in review state rather than preview content.
      • Settled If an input adapter cannot normalize or roll back a browser mutation safely, it reports an operational failure and rebuilds the visible projection from Lexical review state; it never invents different semantics for that browser.
